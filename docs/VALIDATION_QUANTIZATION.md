# Matrix 技術驗證：量化精度損失分析（第 1 部分）

驗證鏈共三段：①量化前後的辨識精度損失、②NPU 推論延遲、③LLM 建議品質。本檔是 ① 的結果；② 需要板子 USB 網路（目前斷線），③ 尚未開始。

## 方法
- 資料：UEC FOOD 100 驗證集 2,109 張（YOLO11s／512px 現行版）、1,909 張（舊 YOLO11n／416px）。
- **框層級 mAP**（IoU 0.5 與 0.5:0.95，101 點內插，類別平均），不是先前的「影像層級召回」。
- 浮點側用 onnxruntime 重現板端 `matrixrt_yolo` 的做法：整張圖直接拉伸成正方形、RGB、/255、每個 anchor 取最高分類別、類別內 NMS 0.45。解碼方式與板端相同，所以和 NPU 的差異只來自量化。
- NPU 側解析板子實跑 `matrixrt_yolo --conf 0.05` 的輸出（含框座標）。
- 所有數字都在信心值 ≥ 0.05 下計算，所以絕對值低於 Ultralytics 官方驗證（conf 0.001）的 0.782／0.610。比較看相對差距。
- 腳本：`training/eval/quant_eval.py`、`qe_eval2.py`。

## 結果一：現行模型（YOLO11s／512px，2,109 張）

| 設定 | mAP50 | mAP50-95 |
|---|---|---|
| 浮點，letterbox，多標籤解碼（接近 Ultralytics 驗證流程） | 0.741 | 0.583 |
| 浮點，letterbox，單類別解碼 | 0.723 | 0.569 |
| 浮點，拉伸，多標籤解碼 | 0.707 | 0.545 |
| **浮點，拉伸，單類別解碼（板端等效）** | **0.684** | **0.528** |
| **NPU 量化後（`.nb`，200 張校正圖）** | **0.682** | **0.522** |

- **量化損失：mAP50 −0.002、mAP50-95 −0.006**（相對約 0.3%、1%），可視為幾乎無損。
- 同一個 NPU 輸出用不同順序處理同分偵測時 mAP50 會差約 0.001–0.002（0.6804 對 0.6818），所以 0.002 的差距在雜訊範圍內。
- 與先前的影像層級結果一致（信心值 0.3 時召回 73.2% 對 72.0%）。

### 類別層級（AP50，NPU − 浮點）
掉最多：cabbage_roll −0.115、seasoned_beef_with_potatoes −0.105、boiled_fish −0.096、shrimp_with_chill_source −0.066、sashimi −0.062。
反而變好：beef_noodle +0.131、sauteed_vegetables +0.073、fried_rice +0.061。
單類驗證樣本只有十幾到幾十張，這些正負變動多半是小樣本雜訊，不代表量化對特定類別有系統性影響。

## 結果二：整條部署流程比量化本身更傷精度
從 Ultralytics 風格的流程走到板端流程，mAP50 共掉 0.059（0.741 → 0.682），拆解如下：

| 步驟 | mAP50 變化 |
|---|---|
| 多標籤 → 單類別解碼（板端每個 anchor 只取最高類別） | −0.019 至 −0.023 |
| letterbox → 直接拉伸（板端 `matrixrt_yolo` 的前處理，模型是用 letterbox 訓練的） | −0.019（多標籤時）／−0.039（單類別時） |
| 量化（FP32 → NPU） | **−0.002** |

量化只占總損失的約 3%。精度主要損失在前處理與解碼的不一致。
這也表示有不用重訓就能回收精度的空間（預估 mAP50 最多約 +0.04 至 +0.06）：在常駐偵測程序 `matrixrt_yolod` 改用 letterbox 前處理與多標籤解碼。
**但這個預估尚未在板上驗證**：校正圖當初是用拉伸前處理做的，改前處理後量化分布可能不完全吻合，需要實測，必要時用 letterbox 重新校正與量化。

## 結果三：量化設定的影響（舊 YOLO11n／416px，1,909 張）

| 設定 | mAP50 | mAP50-95 |
|---|---|---|
| 浮點，拉伸，單類別解碼 | 0.568 | 0.434 |
| NPU（60 張校正圖） | 0.459 | 0.340 |

舊 11n 量化損失高達 **mAP50 −0.110（相對約 19%）**，現行 11s 只有 −0.002。可能的原因有模型尺寸、輸入解析度與校正圖設定（11s 用 200 張、每類平衡取樣）的差異，但**目前無法歸因到單一因素**，因為只剩 60 張校正圖那一組的 NPU 輸出。

## 這份驗證的限制
1. 校正圖張數的消融（1／20／60／200 張）沒有完整做：11s 只有 200 張一組；11n 只有 60 張一組有保存輸出。完整做需要重新量化（VM 約 10 秒／張）並上板重跑。
2. 所有數字在信心值 ≥ 0.05 下計算，沒有 0.001 的完整 PR 曲線。
3. 驗證集來自訓練資料的同一資料集（UEC FOOD 100，日式料理），不代表台灣實際餐點的表現。
4. 只比較了 mAP 與召回、精確度，沒有量化「對營養計算結果」的影響（例如熱量誤差）。
5. NPU 輸出是之前一次板上跑的，沒有重複多次確認輸出的確定性（NPU 推論本身應為確定性）。
