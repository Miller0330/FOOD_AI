# Matrix：偵測前處理改為 letterbox（上線與新舊對照）

## 做了什麼
- `matrixrt_yolod` 新增 `--letterbox`（等比縮放並補灰邊，與訓練一致）與 `--remap`（把框座標由 letterbox 空間換算回「原圖拉伸成 512×512」座標）。
- `platforms/matrix/detector100.py` 預設啟動常駐程式時加上這兩個選項；設定環境變數 `YOLOD_LETTERBOX=0` 即可退回舊做法。
- 因為座標在偵測程式內已換回舊座標系，`main.py`、`food_logic.py` 與網頁疊圖完全沒改。
- 沒有用多標籤解碼（會讓同一物體出現多個框、熱量重複計算，另案評估）。
- 板上備份：`/data/yolod/matrixrt_yolod.bak_stretch`、`Detector100.py.bak_stretch`。

## 換算正確性
用 `--letterbox --remap` 跑完整 2,109 張驗證集，在拉伸座標下算 mAP50 = 0.7187（letterbox 空間下為 0.7187），代表換算沒有誤差。
另外上傳直式（287×446）、4:3、2:1、2.76:1 的照片到線上 `/detect100`，把網頁回傳的框畫回原圖，框都貼合食物（見 `letterbox_overlay_check.png`，紅＝新、綠＝舊）。

### 對營養計算的影響
- 兩種方法在 0.3 門檻下偵測到的類別集合不同的圖片：509／2,109（24%）。
- 熱量誤差（相對「以真實標註類別、預設份量」估算的熱量）：絕對誤差平均 112 → 107 kcal；中位數兩者都是 0。誤差變小的有 289 張、變大的 235 張，其餘 1,585 張相同。
- 改善幅度小：熱量面的進步主要來自「多抓到一些原本漏掉的食物」，但也有新增的誤判。

## 限制
- 這裡的「真實熱量」是以標註類別乘預設份量，並非實際秤重與營養標示，只能比較相對差異。
- 驗證集是日式料理；對台灣餐點的效果未驗證。
- 納入營養的門檻 0.3 沒有調整；letterbox 後信心值分布略有不同，之後可重新評估。
